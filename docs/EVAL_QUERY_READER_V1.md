## 冻结比较

1. 每题一次纯文本Qwen3-VL-8B/NF4规划，共8次：仅输入原始问题，不输入选项字段、正确答案或GT时间。
   生成1–3条不超过120字符的可观察事件短句，并记录回答焦点与时间关系。问题自身含备选陈述时不替用户判真。
   规划先落盘冻结，才打开旧oracle准备文件。无人工修订、静默回退或失败重试。
2. 三组查询：原问题；官方CLIP tokenizer每60内容token分块、最多3块；生成事件短句。
   多句相似度逐帧取最大值，仅是OR式候选召回，不实现AND/先后顺序，也不是置信概率。
   单次编码句数不完全匹配；分块组是长度控制而非完美的句数控制。
   三组共享上一轮全片均匀192帧的相同源PTS、图片和QuickGELU特征，冻结E4/top5/NMS.9，选16帧规则不变。
   原问题重新编码并核对旧曲线（绝对误差不超过2e-6）与送审时刻。新图片编码/抽帧必须为0，否则中止。
3. Oracle输入接口2×2：JSON列表选项/显式A.B.选项 × JSON回答/单字母回答。
   复用旧 `oracle_video16` 的8条列表+JSON预测；另外三组24次新调用。
   所有组使用同16张已知证据原图、相同SHA/源PTS、65536像素原生video；不补上下文。
   单字母用官方tokenizer确认每个选项是单token，约束生成1token。提示指令和解码一同变化，称“接口对照”，不声称语法的纯因果效应。
4. 主评测三组各最多8次，共24次：预先固定显式选项+JSON，不根据oracle成绩选接口。
   原完整问题和16帧送入回答器，不提供生成短句；展示前2候选中实际含有送审帧的区间及源PTS。
   模型只能返回选项+候选ID，或abstain+none；不允许生成时间。ID确定性映射合法半开浮点秒区间。
   无可见候选则确定性弃答、不调用模型；无效ID/回答配对留在失败分母。
   这是候选选择与回答耦合，不是独立语义验证器；选择ID也不证明证据正确。

### 完成后只读失败审计

本节明确为事后诊断，未改写冻结方法、未增加推理、未使用备选方法分数调参。

- 原问题和token分块：送审帧命中GT的4题中，3题的命中帧仅来自候选外的补充帧；允许引用的候选里只有1题的展示帧命中GT，且没有任何候选IoU≥.5。唯一合格的top5区间排第3，未进入可引用的前2候选。
- 事件短句：送审帧命中GT的4题中，2题的命中帧只在候选外；两题top5有合格区间，分别排第2和第5。第2名已可引用但回答器选错候选且答错，第5名没有进入可引用集合。
- 因而存在两个不同的损失：候选/展示/引用之间不一致，以及候选已可用时的语义判断错误。不能仅凭“看到了GT时刻”或“返回合法ID”证明找到了有效证据。
- 定性阅读规划发现：一条“when”问题被标成causal，一条“why”问题被标成first；“第一次经过路口”的检索短句退化成车辆/路口名词，时间约束仅在未被检索使用的元数据中；多属性问题受到三句上限影响而遗漏另一对象属性。没有人工修订这些输出。本段不是盲评或规划语义准确率。
- 生成20条短句（4题两条、4题三条），token分块只有1题产生两块。最大值融合不保留关系，各组句数不同；不能把变化唯一归因于“语义分解”。
