# 候选内观察与有界补看（2026-11-07）

以下协议在真实运行前冻结，本轮已完成，结果见文末。同8个反复使用的开发来源，仅用于机制诊断，不是独立泛化验证。保留所有历史轮次，不替换产品默认路径、不训练、不扫描提示/阈值。

## 候选与观察

复用已冻结原问题dense_uniform检索的top5 E4区间。上一轮送审16帧中未被这些区间覆盖的帧，按原CLIP分数降序、时间升序，最多补3个64秒搜索窗口；每加入一个窗口即覆盖相应种子，边界截在视频内。单帧仅触发搜索假设，不是事件边界或证据。未纳入的旧补充帧计数留档。
每候选重新提取8个bin中心的真实源PTS图，最大边1024。每张展示图都属于一个可引用候选，禁止候选外全局帧补齐。模型输入使用带实际时间/索引的独立images；同轮所有对照使用相同底图、像素65536。重叠候选中的重复展示计入成本。
相对旧轮同时改变候选池、局部采样和images输入，不能把跨轮变化单独归因于绑定修复。

## 冻结对照与预算

- joint_forward：一次看全部候选图片，原顺序，返回选项+候选ID或弃答。
- joint_reverse：完全相同图片多重集，候选块反序且ID保持；检查模型位置敏感性，不选择表现更好的顺序作为主方法。
- packet_verify：每候选独立调用，保留完整问题的主体/动作/对象/属性/首次/先后/时长；输出supported、contradicted或insufficient、选项/弃答、证据帧索引、缺失类型和简短可见事实。
- packet_observe：复用全部初判。无支持候选时，对排序最前、缺失可由局部观察解决的insufficient候选最多补看一次：同一区间新增16帧，与原8帧合并为24帧再判断。global_scope不假装能通过局部加密解决；明确矛盾不触发同节点补看。预算耗尽仍无支持则弃答。

supported需至少2个不同的合法帧引用、有效选项、无缺失；contradicted需至少1帧展示明确冲突，不能由未看到目标推断；insufficient必须弃答并记录缺失。模型判断仍是待核查的主张，格式合法不等于真实。
多个supported候选若答案一致按冻结检索顺序选；答案冲突则弃答。固定代码负责动作和时间映射，不训练新Agent策略，不让模型编写时间。
每题最多8候选；8题最多88次调用（16联合+64独立+8补看），最多640张新图；零CLIP新编码、零重试。逐候选与联合的基础图片内容一致，但调用次数/文本token不同，不称同计算预算；补看组另有额外观察成本。批量初判后才决定一次补看，不称完整在线树搜索。

先Mock合成视频与pytest，再冻结源码/配置部署。准备和推理不接触GT；生成结束后独立评估器读标签。记录候选IoU上限、帧覆盖、QA、joint@.5、弃答、结构失败、动作、顺序差异和全部成本，失败保留在8题分母。无需观察之外的证据推断全局首次/最后，不把候选长度当事件时长。
