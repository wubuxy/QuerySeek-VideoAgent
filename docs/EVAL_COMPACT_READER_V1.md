# 精简核验与事实映射：冻结协议（2026-11-08）

本轮已完成，结果追加于文末。先前84次实验已结束，不重复。本轮全部使用固定Qwen3-VL-8B-Instruct BF16、SDPA、每图262144像素、16张独立图像、贪心生成、512输出token上限、零重试。模型快照沿用既有固定revision。研究目标是修复接口兼容与事实—选项失配，不训练、不替换产品默认策略。

## 两个阶段，事前固定全部条件

开发阶段沿用旧8来源的oracle16张图，不重采样、不输入人工提示。新来源阶段选择8个此前CG-Bench实验未使用的视频，每来源一题；先固定选择、方法和评测，再运行两个阶段，不用开发成绩挑选新来源或方法。全部新来源条件无论开发分数如何均运行；仅工程错误/资源故障允许中止，并保留完整失败分母。

方法：

- `minimal`：现有最简强制作答提示/JSON回答。同开发正图8条BF16结果严格核对后复用，新来源和错来源条件新运行。它无弃答功能，覆盖率与可弃答方法分开看。
- `compact`：明确分隔任务输入和输出schema，只返回`answer`（选项或abstain）与`evidence`（整数图像索引数组）。最多4引用；作答必须非空、弃答必须空。无多分支状态、区域、生成计划或长描述。结构检查不是语义验证。
- `fact_map`：第一步只给原题和图片，不给独立choices字段，返回一条简短可见事实及引用；原题内已含备选陈述时不删改。第二步无图，只给原题、选项和这条事实，将事实映射为选项或abstain；不接触标注答案。空引用不能支持作答。两步分别记录原文、成本与有效性；错误不修复。
- `agreement`：预先固定的派生结果，只有compact与fact_map均有效且给出相同非弃答选项才接受，否则弃答。复用两方法输出，没有新增推理。它需要三次调用且共享同一模型与图像，并非独立证据或等预算比较。

另外开发阶段仅做8次`legacy_explicit`：在原复杂核验提示中明确划分输入块，并将原schema明确展示为输出契约；原计划、schema、图片、模型和输出上限不变，对照先前BF16复杂核验8条。该项只诊断显式格式说明，不进入新来源方法选择。

三个主要方法同时接受正来源oracle图与错来源图。错来源按各组固定请求顺序循环使用下一个不同视频的16帧，保留供图来源真实PTS。称“错来源接受率”，不将其自动当作经人工认证的假阳率；不同来源也可能偶然出现相似物体。正来源答对不证明定位正确或引用充分，因为时间证据是特权输入。

预算：开发阶段新64次（minimal错图8，compact正/错16，fact_map正/错32，legacy_explicit8），复用旧minimal正图8和旧复杂核验8。新来源新64次，合计最多128次新生成。无重新规划、无新CLIP编码。方法调用数/图像展示不完全相等，费用单列。

## 输出验证与报告

所有接口仍使用浮点秒和半开区间，引用绑定实际源PTS。图像SHA、处理后pixel tensor摘要、真实grid与视觉token数量均留档。正/错来源身份不能混淆；对应方法的同源图片处理摘要应一致。第二步事实映射必须无视觉tensor。不得将裁切/重复帧当成独立时刻。

逐组/逐方法报告全分母有效率、作答数、正确数、错误作答数、已作答正确率；错来源报告作答率和相对正来源的答案变化。派生agreement不能重复计入物理调用成本；方法逻辑成本包括所依赖步骤。描述与选项一致不保证事实真实，不宣称独立验证器。原始输出、无效字段、截断和失败全部留档，不事后提取/补全答案。

代码/配置/选择/输入在推理前冻结。每阶段独立manifest并拒绝覆盖；OOM或连续3次后端失败停止剩余推理，保留失败分母。首个阶段不向模型读取labels，新来源原始问题/媒体不公开；公开仅代码、协议与聚合数据。Mock使用统一合成fixture验证全流程，不报告真实准确率。

### 结果解释与事后诊断

新来源上compact与minimal答对相同5题、答错相同3题，7/8最终选项完全一致（另1题两者均错但选项不同）。compact在8个错来源输入上全部弃答，且每题只需1次调用。这支持把它作为带引用、可弃答的研究基线，但没有显示问答正确率提升。开发来源上它新增1个正确、丢失2个正确，进一步说明不能宣称普遍改善。

fact_map的新来源6次弃答全部发生在第一步已提供非空引用之后，并非被空引用硬规则挡住；它没有新增正确，丢失minimal原有的4个正确。阅读原始记录可见第一步遗漏目标属性、把关注点转向旁支事件，以及跨语言指代失败；第二步仅能依据这份文字判断。原始输出已保留，未重写事实或从其他字段补分。独立选项字段、提示、解码任务与调用次数同时变化，不能将损失全部归因于“思维链”或模型规模。

事后输出长度审计显示：开发6/8、新来源8/8事实字符串恰为320字符，且分别有6/8、8/8超过提示要求的40个空格分词；最长事实步骤输出209 tokens，未达到512-token总上限。部分文字重复元数据或在句子中间收尾。JSON与引用通过校验不代表事实表达完整；目前没有长度/解码单因素消融，不能断言提高字符上限就能恢复正确率。原始字符串没有Unicode替换字符；控制台乱码未计为模型错误。

agreement在新来源只保留2个答案，1对1错，丢掉minimal原有4个正确；保留的错误也出现在两条路径中。同模型的一致性不能当独立证据。显式说明旧复杂schema把开发作答从1题增到6题，但新增的5次作答只有1次正确，错误作答从1题增到5题：接口明确只改变了输出行为，没有解决语义可靠性。

新来源正图每题平均处理与生成用时：minimal约1.98秒、compact约2.55秒、fact_map约7.09秒、agreement约9.64秒（后者累计依赖调用，非额外生成）；不含抽帧、模型加载和检索。该时延口径不能充当完整产品端到端延迟。

少量原图的事后人工复核还发现，正确选项的引用未必覆盖全部对象/事件条件。当前错来源是不同视频的粗粒度干扰，没有证明同视频错误时段、相似对象等困难负例也能拒答；没有对引用语义充分性全面人工标注。下一步应冻结这些更接近实际检索的条件，并将时间边界定位与秒数计算分别评估。这些是后续建议，尚未实测；产品默认策略未更改。
