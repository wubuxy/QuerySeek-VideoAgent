# CLIP变化时间树：冻结开发检查（2026-11-07）

用户已授权开始实现。目标是把固定二分节点替换成可按视觉变化展开的多子节点候选，并验证单张A5000上的运行与成本；不把切分成功等同于定位/问答成功。

## 范围与事前固定

配置 `configs/scene_tree_probe_v1.json`，沿用已有8来源开发请求和同一份评测标签。构建器只接收无标签请求，且仅将视频路径、实际时长和SHA传给切分器；问题、选项、正确答案、GT都不参与切分与访问顺序。先生成树，再由独立evaluate入口读取标签。无新VLM调用、无训练、旧确认/fresh80不动。
每个视频最多对3个节点进行抽帧/CLIP观察，按时间顺序广度优先访问，最多每节点64帧，总编码上限1536图。不是完整展开所有节点，也不是已经学习的搜索策略。

## 方法与复用边界

直接复用VTS固定commit `184310c5eec2193060a5c95bbda4ad443dae4e25` 的4个纯NumPy边界函数，完整MIT许可随包保留；只抽取函数、未修改函数体。源码位置与SHA见 `THIRD_PARTY.md`。
相邻帧CLIP特征余弦距离超过局部均值+1.5倍标准差时提议切点；不足3个子节点时按最高差异补足，多于8个时保留最高变化。平坦视频强制补足的情况显式记录，不伪称语义变化。边界采用相邻实际源PTS的中点，同时保存两侧观测时刻组成的边界范围；中点是候选切点，不伪装为某张实际帧的PTS。
用现有OpenCLIP ViT-B-32/openai、QuickGELU、FP32、小批量16处理。固定本机已有模型权重SHA `e6d1bd7789aa45192b3bf90570a789b478bae1b74ebcce7eddd908e83a2b7c31`，权重仅传到用户服务器D盘，双端校验，不公开。该编码器选择不代表已经复现VTS原服务配置。
抽帧复用FFmpeg源PTS接口，当前节点按bin中心请求、每秒最多1帧且最多64帧，长边512；这是本项目半开时间契约适配，与上游OpenCV端点采样不同。小于64秒或达到深度6停止展开。根节点可只读复用前轮完全相同抽帧参数的64帧缓存；其余节点按真实时间和配置建立独立缓存。
缓存键包括媒体SHA、pipeline版本、抽帧配置、时间列表、模型权重/激活/预处理/依赖版本；读取时校验图像、索引和特征哈希。历史v1/v2与已有模型实验产物不覆盖。

## 导航接口

`TemporalTree`惰性展开并限制观察节点数；`TreeNavigator`提供指定子节点深入、兄弟切换、返回父节点、补看与状态记录。CLIP用于切分的图片不自动计成回答器已看过的图片；回答器观察帧有独立上限。离开节点保留未知状态，已有帧不丢失，非法节点跳转被拒绝，预算耗尽不伪装成已证明没有证据。
这交付的是可执行工具接口，旧SFT二分适配器和产品LangGraph路径不改；没有声称已训练新导航策略或解决语义拒绝判断。边界细化与问答对照尚未执行。

## 对照和指标

主结构检查只比较根节点的直接子区间，避免将不完整广度优先树当作最优搜索结果：

- 固定二分：历史几何参照，分支数不同。
- 同分支数的均匀切分：与该视频CLIP根节点保持相同子节点数量，检查切点位置；其分支数由CLIP提供，不能称完全独立的部署基线。
- CLIP变化切分：冻结的本方法。

离线报告各方法最佳子区间对全部GT并集的IoU、GT段被完整容纳的比例、每个GT跨越的子区间数量。最佳子区间由评测端GT挑选，只是结构可达性诊断，绝非Agent准确率。所有8题保留分母，失败的重叠/包含成绩记0。
另报实际源PTS是否命中GT、边界观测间隙、子节点数、强制补足次数；未观察区域和短事件可能仍被漏掉。三个节点的完整树只作导航/预算与分区完整性检查，不用GT挑选下一个展开节点。
成本报告新抽帧、复用缓存、编码图数、模型装载、查询预处理总时长、GPU峰值分配显存；包含前处理，不当作VLM生成延迟，缓存成本与首次成本分开。

## 实测结果：2026-11-07

8/8来源完成，0失败；视频时长1157.312–2839.795854秒（约19–47分钟）。每来源观察3个节点，共24个观察节点、145个已创建节点，分区无重叠/空隙且均满足时间契约。根节点分支数为4–8，没有触发强制补足。每条树都通过深入→兄弟切换→返回父节点的工具检查，保留4张历史观察帧和未知证据状态；这不是语义决策策略评测。

| 根节点分区 | 平均最佳子区间对GT并集IoU | GT段完整容纳率 |
| --- | ---: | ---: |
| 固定二分 | 0.026992 | 100% |
| 同分支数均匀切分 | 0.086243 | 100% |
| CLIP变化切分 | 0.088293 | 100% |

CLIP对同分支数均匀切分仅高 **0.205个百分点**，逐来源 **4胜4负**。这8来源不支持“视觉切点稳定更好”的结论；与二分的较大差距混合了分支数量的影响。所有方法的100%容纳率也不能证明已精准定位：很长的候选窗容易容纳短证据。
根节点64帧的实际PTS仅在4/8来源命中GT；切点两侧观测间隔18.08–44.37秒，中位27.02秒。切点是这段未知间隔的中点估计，不能当作精确事件起止。该结果支持进一步检查局部加密观察和跨界上下文，不能直接支持扩大策略训练。
