# 固定证据的模型诊断（2026-11-07）

本协议在新推理前冻结。本轮已完成，实测追加在文末。目的：区分输入链路、分辨率、输出约束、复杂核验和NF4量化；不新增检索策略或训练。

复用此前8个开发来源的`oracle_video16`原图，每题16帧，SHA与真实源PTS不变。它们按标注时间选择，属于特权证据诊断，不能称自主定位或独立泛化成绩。此前人工讨论过3题；本轮不输入人工答案、对象提示或手工框。新benchmark抽帧0。原选项与完整原题保留，帧ID统一为无语义编号，推理不打开标签文件。

## 冻结条件

每题8种条件，共64次，均为同一Qwen3-VL-8B-Instruct固定权重、SDPA、贪心生成、上限512输出token、120秒生成时限、零重试。

1. NF4：65536/262144每图像素预算 × 开启/关闭JSON语法约束，2×2共32次。四组**提示逐字相同**，均要求仅输出答案JSON；非约束输出不修复、不截取解释、不补答案。分辨率组复用相同原图，记录实际grid/视觉token，名义预算不是保证精确像素数。
2. NF4高分辨率：无图8次；错图8次。错图确定性使用冻结请求顺序中的下一来源16帧，保证不同视频；保留供图来源真实PTS。无图不携带帧元数据。所有组使用同一最简问答提示，不提示模型处于oracle/无图/错图条件。比较用于检查图像敏感性；无图或错图答对不证明泄漏，原题和选项本身也可能提供先验。
3. NF4高分辨率：复杂证据核验8次，复用前轮冻结的question-only计划及`evidence_needs`提示、输出契约，允许弃答。共享oracle原图但任务目标/输出长度不同，因此不是语法约束的单因素对照，QA与作答覆盖分开报告；global计划仍禁止局部作答。
4. BF16高分辨率最简JSON 8次，对照NF4高分辨率最简JSON。模型文件、图像、提示、处理器输入、生成参数与解析相同，只有模型加载精度配置变化。顺序卸载NF4后另进程加载BF16，不同时占GPU。仅此一组BF16，不据结果扫描更多量化参数。

另由仓库统一合成fixture生成红/蓝背景各一帧，两精度分别问背景颜色，共4次。合成卡无颜色文件名/帧ID提示进入模型，不与benchmark准确率混计。总上限68次。若OOM立即停止该精度剩余推理，保留全部失败分母；连续3次后端失败同样停止。格式不合法是输出结果，不触发自动重试。

## 输入与评测审计

保存原图SHA、源PTS、尺寸、实际image grid、image token数量、处理后pixel tensor SHA/形状/标准差、输入token ID SHA、提示SHA。图像grid数量必须等于实际图片数，视觉占位token数量必须等于grid压缩后数量，图片tensor必须非空非恒定；文本控制必须无pixel tensor。保存摘要不保存tensor字节或密钥。对NF4/BF16相同条件与同分辨率两解码组核对输入完全一致。

独立评估器才读取冻结答案标签；全8分母，报告有效输出、实际作答、正确数、配对新增/丢失题数、无图/错图答案改变数。此轮不报告定位IoU，因为输入已使用标注时间。结构合法不证明视觉描述或引用可靠。没有统计显著性或模型能力上限主张。

每条件报告输入/输出/视觉token、展示图数、耗时和峰值allocated；模型加载另列。无图天然不是等算力控制。记录原始私有输出供失败检查，公开仅代码、协议、聚合结果。源码/配置/输入哈希冻结，任何实现故障另留修订记录，不能覆盖旧结果。Mock只验证管线，不代表模型准确率。

入口 `scripts/probe_model_diagnostic.py`：prepare → run --precision nf4 → run --precision bf16 → evaluate。使用服务器已有模型与依赖，不下载新权重。检查 `tests/test_model_diagnostic.py` 后再运行。

## 结果能支持什么

同输入BF16比NF4新增答对2题、未丢失正确题。这说明量化配置是本开发诊断里值得保留的影响因素，不能据8题断言4-bit普遍损失25个百分点。提高每图像素预算反而丢失1题，没有新增正确；高分辨率不能单独解决问题。最简问答下开启/关闭JSON约束，16组配对答案全部一致；复杂schema是否改变生成分布，需要单独对照，不能由最简schema结果推断。

三个已人工讨论的静态案例，本次原图能够展示相关目标及其属性；其中一个界面有明确归属标题，解决了前轮错误候选的归属疑问。一个静态案例在各带正确图的最简条件中均答对；另一个在NF4低分辨率和BF16高分辨率中答对，NF4高分辨率答错；第三个在最简条件中仍答错，而复杂核验的描述与最终决策相矛盾。原题、对象特征、具体答案和媒体只保存在私有复核中。这是事后定性观察，不是新增盲评指标，没有用于改写推理输入。

更明显的失配发生在复杂核验：三个静态案例的描述已经写出所需属性，却全部给出`attribute_unreadable`；另一个时长案例的描述明确对应一个选项，最终决策却选择不同的选项。因此错误包含视觉/指代判断、描述与决策不一致和选项映射多个层次，不能统一归因为“模型完全没看见”。无图仅1题、错图0题答对，错图改变全部8个答案，加上色卡与输入审计，支持图像链路在本轮确实影响了模型回答；这不保证每个答案都忠实于图像。

复核原始输出的CPU解析器审计：三个静态案例保持所有字段和文本不变，仅替换decision为各合法答案分支，均可被原解析器接受。因此它们的正确答案没有被契约直接排除。其余案例中global计划禁止局部回答、temporal的单帧引用也不能直接换成回答；另外2条含Unicode替换字符的输出未能进行完整字符级重放，字符级结果不能等同于原始BPE token轨迹。本审计不新增模型调用。

基于上述结果，另行冻结16次复杂核验的自由解码/BF16跟进，见[EVAL_VERIFIER_DIAGNOSTIC_V1.md](EVAL_VERIFIER_DIAGNOSTIC_V1.md)。它是事后假设验证，不并入本轮事前68次矩阵。
